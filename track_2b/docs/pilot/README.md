«durch BAG zu ergänzen» markiert. Es wurde kein Kontakt mit dem BAG aufgenommen.

**Das Paket als eine Datei (Variante A):** `make pilot-pack` (oder `python3 tools/pilot_pack.py`) schreibt
`dist/gleichlaut-pilot-phase1-20261006.zip` und daneben dessen sha256. Inhalt: das Register als eine HTML-Datei, offline
lesbar (`register/gleichlaut-register.html`), die Fallblätter als Markdown und PDF, Entscheidvorlage, Management-Notiz,
Schutzbedarfsanalyse, Projektauftrag und `SHA256SUMS`. Gleicher Inhalt, gleiche Bytes, unabhängig von Commit-Zeit,
Uhrzeit und Rechner (fester Zeitstempel 06.10.2026, die Code-Revision im Register ist ein Inhaltshash von `src/`); kein
Modell, kein Netz. Die ZIP-Datei wird nicht eingecheckt (`dist/` ist gitignoriert). `make pilot-pack` bricht ab, wenn
Fallblätter oder PDFs nicht dem Stand des Repositoriums entsprechen.

**Echtheit prüfen.** `SHA256SUMS` liegt im Paket und belegt deshalb nur, dass die Dateien zueinander passen: wer die
ZIP-Datei verändert, kann `SHA256SUMS` mitändern. Massgeblich ist der Wert unten, der im Repositorium steht (in der
Git-Historie nachvollziehbar) und den `python3 tools/pilot_pack.py --check` sowie `python3 tests/run.py pilot` gegen den
Stand des Repositoriums prüfen. So prüft die Empfängerin ein erhaltenes Paket:

1. Den Commit (oder Tag) aus der Begleitnachricht auschecken: `git clone <repo> && cd gleichlaut && git checkout <commit>`.
2. Neu bauen: `cd track_2b && make pilot-pack`; die Ausgabe nennt die sha256 der gebauten ZIP-Datei.
3. Vergleichen: `shasum -a 256 gleichlaut-pilot-phase1-20261006.zip` (erhaltene Datei) = Ausgabe von Schritt 2 = Wert
   unten in diesem Commit. Weichen nur die ZIP-Bytes ab (eine andere zlib-Version komprimiert anders), entscheidet der
   Inhalt: im entpackten Ordner `shasum -a 256 SHA256SUMS` = «sha256 von SHA256SUMS» unten, dann
   `shasum -a 256 -c SHA256SUMS`.

Signieren ist Sache des Betriebs: Wer das Paket weitergibt, signiert die ZIP-Datei mit dem Schlüssel des Amts (z. B.
`cosign sign-blob --key amt.key gleichlaut-pilot-phase1-20261006.zip > paket.sig` oder
`minisign -S -m gleichlaut-pilot-phase1-20261006.zip`), die Empfängerin prüft mit `cosign verify-blob` bzw.
`minisign -V`. Dieses Repositorium erstellt keine Releases, Tags oder Signaturen.

(Abweichung = Exit 1); Fallblätter eines eigenen Laufs (z. B. monatlich mit `make audit` nach `out/audit/`):

bricht ab, wenn seine Zählung nicht mit `eval/results/audit_relabel.json`, `audit_r15.json` und `audit_grouping.json`

**English summary.** This folder is the phase-1 pilot pack for a federal office, in German: a one-page decision memo in front
(phase 1 only; who signs each remedy and on which basis only as far as docs/sl-process.md sources it, everything else
left to the legal service), a note for the
head of section, a draft project mandate on the HERMES structure, a draft protection-needs analysis on the structure of
the federal P041 template, and one case sheet per audit issue, ready to file in GEVER (18 issues from the 6 Oct 2026
run plus the 6 confirmed findings of the experimental checks, which are off by default). Phase 1 uses no model, no ePL
access and no purchase. Every owner, contact and date is left as «durch BAG zu ergänzen»; labels are by blind Claude
annotators, not by BAG. The sheets are generated by `tools/pilot_sheets.py` and checked by `tests/test_pilot_sheets.py`;
`tools/pilot_pdf.py` renders the memo, the note and the sheets to PDF (committed under `pdf/`, `--check` by source hash);
`make pilot-pack` builds the whole pack, with the offline register and SHA256SUMS, as one reproducible zip in `dist/`;
its expected sha256 is recorded above (`tools/pilot_pack.py --check`, tested), so a recipient rebuilds from the same commit
and compares; signing the zip (cosign, minisign) is the operator's step.
